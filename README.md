# Онлайн-платформа по обучению музыке (Music Learning Platform)

Проект по курсу «Операционные системы»: контейнеризация многокомпонентного веб-приложения и реляционной базы данных с использованием Docker и Docker Compose.

---

## 1. Описание архитектуры и компонентов системы

Система построена по трехзвенной архитектуре (3-tier) и разделена на 3 изолированных Docker-контейнера:

1. **`music_frontend` (Клиентская часть):**
   - React 18 (SPA) собран через Vite.
   - Запущен в оптимизированном легковесном контейнере `nginx:1.25-alpine`.
   - Выполняет роль веб-сервера для раздачи статических ресурсов и reverse proxy для перенаправления запросов `/api/` и `/uploads/` на бэкенд.
   - Опубликованный внешний порт: `3000`.

2. **`music_backend` (Серверная часть):**
   - Node.js 20 (Express, Sequelize ORM).
   - Запущен в контейнере `node:20-alpine` от имени непривилегированного пользователя `node` (non-root security).
   - Предоставляет REST API, валидацию данных, аутентификацию (JWT) и бизнес-логику платформы.
   - Реализует эндпоинт мониторинга состояния `/health`.
   - Внутренний порт: `5000` (в Docker-сети).

3. **`music_db` (База данных):**
   - Реляционная СУБД PostgreSQL 16 (`postgres:16-alpine`).
   - Изолирована во внутренней Docker-сети `music_network` (порт 5432 закрыт от хост-машины).
   - Данные сохраняются в именованном томе `music_postgres_data`.
   - Файлы пользователей сохраняются в именованном томе `music_uploads_data`.

## 3. Требования к окружению

- **Операционная система:** Windows 10/11 (с включенным WSL2), macOS или Linux.
- **Docker Engine:** версия 24.0+ (или Docker Desktop).
- **Docker Compose:** версия 2.20+.

## 4. Пошаговая инструкция по запуску

### Шаг 1. Клонирование репозитория и переход в папку проекта
```bash
cd project
```

### Шаг 2. Подготовка файла переменных окружения
Скопируйте шаблон `.env.example` в `.env`:
```bash
# Windows PowerShell:
Copy-Item .env.example .env

# Linux / macOS:
cp .env.example .env
```
При необходимости отредактируйте параметры в файле `.env`.

### Шаг 3. Сборка и запуск контейнеров
Запустите все сервисы в фоновом режиме:
```bash
docker compose up -d --build
```

### Шаг 4. Проверка статуса работы контейнеров
Убедитесь, что все контейнеры запущены и находятся в статусе `healthy`:
```bash
docker compose ps
```

### Шаг 5. Открытие приложения
Откройте браузер и перейдите по адресу:
- Веб-приложение: **http://localhost:3000**
- Проверка работоспособности (Healthcheck): **http://localhost:3000/api/health**

## 6. Резервное копирование и восстановление базы данных

### Создание резервной копии:
Скрипт автоматически выполняет команду `pg_dump` внутри контейнера `music_db` и сохраняет SQL-дамп в папку `backups/`:
- В PowerShell:
  ```powershell
  .\scripts\backup.ps1
  ```
- В Linux / Bash:
  ```bash
  chmod +x ./scripts/*.sh
  ./scripts/backup.sh
  ```

### Восстановление из резервной копии:
Скрипт восстанавливает базу данных из последнего созданного дампа:
- В PowerShell:
  ```powershell
  .\scripts\restore.ps1
  ```
- В Linux / Bash:
  ```bash
  ./scripts/restore.sh
  ```

## 8. Возможные ошибки и способы их устранения

1. **Ошибка `failed to connect to the docker API` / `daemon not running`:**
   - *Причина:* Не запущен демон Docker Desktop.
   - *Решение:* Запустите приложение Docker Desktop в Windows и дождитесь появления зелёной иконки "Engine running".

2. **Порт 3000 уже занят на хост-машине:**
   - *Причина:* Другое локальное приложение использует порт 3000.
   - *Решение:* В файле `docker-compose.yml` измените проброс портов сервиса `frontend` на `"3001:80"` или остановите конфликтующий процесс.

3. **Бэкенд не может подключиться к БД при первом запуске:**
   - *Причина:* Инициализация кластера PostgreSQL заняла больше времени.
   - *Решение:* В `app.js` встроен автоматический цикл повторных попыток подключения (10 попыток с интервалом 3 секунды). Также в `docker-compose.yml` настроен `depends_on: { db: { condition: service_healthy } }`.
